# Account Management

Payment accounts go through a defined lifecycle managed via the Accounts API. After the onboarding flow creates the account (state: `pending_kyc`), your integration activates it, and from there you can block or reserve accounts as needed.

## Account State Machine

```
pending_kyc
    │
    ▼
 active ──────────────────┐
    │                     │
    ├──► suspended        │
    │                     │
    ├──► blocked ◄────────┘
    │
    └──► closed (terminal)
```

| State | Description |
|-------|-------------|
| `pending_kyc` | Account created, awaiting KYC approval |
| `active` | Fully operational, can send and receive |
| `suspended` | Temporarily restricted |
| `blocked` | All operations halted |
| `closed` | Terminal state — cannot be reopened |

<Callout intent="warning">
  State transitions are **one-way** for destructive states. A blocked account cannot be reactivated directly. `closed` is irreversible.
</Callout>

## Activating an Account

After KYC documents are approved, transition the account from `pending_kyc` to `active`:

```bash
curl -X POST https://api.brzip.com.br/api/v1/accounts/{accountId}/activate \
  -H "Authorization: Bearer <your-jwt>"
```

No request body is required.

**Response (200):**

```json
{
  "account_id": "a612b202-6690-4d24-ba35-2e36c8f3c0ce",
  "status": "active"
}
```

After activation, an `account.activated` webhook event is fired to your configured endpoint.

**Errors:**

| HTTP | Code | Meaning |
|------|------|---------|
| 404 | `ACCOUNT_NOT_FOUND` | Account ID does not exist |
| 409 | `INVALID_STATE_TRANSITION` | Account is not in a state that allows activation |

## Blocking an Account

Block an account to halt all financial operations. Provide a `reason` for audit trail:

```bash
curl -X POST https://api.brzip.com.br/api/v1/accounts/{accountId}/block \
  -H "Authorization: Bearer <your-jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Suspicious activity detected"
  }'
```

**Response (200):**

```json
{
  "account_id": "a612b202-6690-4d24-ba35-2e36c8f3c0ce",
  "status": "blocked"
}
```

**Errors:**

| HTTP | Code | Meaning |
|------|------|---------|
| 400 | `MISSING_REASON` | `reason` field is empty or absent |
| 404 | `ACCOUNT_NOT_FOUND` | Account ID does not exist |
| 409 | `INVALID_STATE_TRANSITION` | Account is not in a state that allows blocking |

<Callout intent="info">
  Blocked accounts stop all PIX, boleto, and P2P operations immediately. Pending transactions already in flight will complete normally.
</Callout>

## Reserving an Account

Reserve an account slot before completing the full onboarding. Useful when you need to capture a client's identity early:

```bash
curl -X POST https://api.brzip.com.br/api/v1/accounts/reserve \
  -H "Authorization: Bearer <your-jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "reference_id": "onb_my-idempotency-key",
    "account_type": "PF"
  }'
```

**Request fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `account_number` | string | No | Specific number to reserve — omit for auto-assignment |
| `reference_id` | string | Recommended | Idempotency key; if omitted a random UUID is generated per call |
| `account_type` | string | No | `"PF"`, `"PJ"`, or `"ESCROW"` |

**Account types:**

| Type | Description |
|------|-------------|
| `PF` | Individual (Pessoa Física) — requires CPF |
| `PJ` | Business (Pessoa Jurídica) — requires CNPJ |
| `ESCROW` | Escrow account for holding funds |

**Response (201):**

```json
{
  "account_number": "9876543",
  "reservation_id": "res_3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "branch_code": "0001",
  "reference_id": "onb_my-idempotency-key"
}
```

**Errors:**

| HTTP | Code | Meaning |
|------|------|---------|
| 409 | `ACCOUNT_NUMBER_UNAVAILABLE` | Requested `account_number` is already in use or reserved |

## Account Capabilities

Once an account is active, its capabilities depend on the KYC level. Higher KYC levels unlock higher limits and additional operations.

| Capability | KYC Level 1 | KYC Level 2 | KYC Level 3 |
|------------|:-----------:|:-----------:|:-----------:|
| Receive PIX | ✓ | ✓ | ✓ |
| Send PIX (low value) | ✓ | ✓ | ✓ |
| Send PIX (high value) | — | ✓ | ✓ |
| TED | — | — | ✓ |
| Boleto payments | ✓ | ✓ | ✓ |

<Callout intent="info">
  PIX cash-out requires **step-up authentication** (`X-Step-Up-Token`) for amounts above the configured threshold. See the [Cash-Out guide](./guide-cash-out) for details.
</Callout>
