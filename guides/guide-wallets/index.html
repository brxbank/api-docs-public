Wallet Balance

Query real-time wallet balances for the authenticated client.

Wallet Balance

The Wallet API returns real-time balances for the wallets owned by the authenticated client. Balances are cached (5-minute TTL) and invalidated automatically when the ledger processes a transaction.

ℹ️

These endpoints require Bearer Token or API Key authentication with the pix:balance:read scope. Ownership is scoped to the client_id in your token — you can only read your own wallets.

List Wallet Balances

Returns every user-visible wallet owned by the authenticated client (checking plus any benefit pockets):

curl -X GET https://api.brzip.com.br/api/v1/accounts/wallets \
  -H "Authorization: Bearer <your-jwt>"

Response (200):

{
  "success": true,
  "data": {
    "wallets": [
      {
        "id": "b1c2d3e4-f5a6-7890-bcde-1234567890ab",
        "account_id": "a612b202-6690-4d24-ba35-2e36c8f3c0ce",
        "wallet_type": "checking",
        "available": "1250.50",
        "blocked": "50.00",
        "total": "1300.50",
        "currency": "BRL",
        "updated_at": "2026-07-22T10:30:00Z"
      }
    ]
  }
}

List Balances for a Specific Account

Returns the wallets that belong to one account_id. Ownership is still enforced by the client_id in your token — an account owned by another client returns no rows:

curl -X GET https://api.brzip.com.br/api/v1/accounts/{accountId}/wallets \
  -H "Authorization: Bearer <your-jwt>"

The response shape is identical to the list endpoint above.

Balance fields explained

Field Description
id Wallet identifier
account_id Account the wallet belongs to
wallet_type Wallet type (e.g. checking)
benefit_code Benefit code, present only for benefit-pocket wallets
available Funds available for immediate use
blocked Funds held for pending transactions
total available + blocked
currency Currency code (e.g. BRL)
updated_at Timestamp of last balance update

Cache Behavior

Balance is cached in Redis with a 5-minute TTL. Cache is automatically invalidated when the ledger processes a transaction event: ledger.hold.created, ledger.capture.created, ledger.release.created, ledger.credit.created, and ledger.debit.created.

Error Reference

Errors are returned with this envelope:

{
  "success": false,
  "error": {
    "code": "WALLET_NOT_FOUND",
    "message": "human-readable message"
  }
}
HTTP Code Meaning
401 UNAUTHENTICATED Missing or invalid credentials
400 INVALID_ACCOUNT_ID accountId is not a valid UUID
500 DB_ERROR Internal error — retry with exponential backoff
