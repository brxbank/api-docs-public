Boleto Payments

The Boleto API allows your clients to pay boletos using funds in their BRZ wallet. The integration uses Celcoin as the underlying provider, orchestrated by the payment service.

Payment Flow

1. Decode barcode       →  retrieve beneficiary + amount
2. Authorize payment    →  submit payment (deducts from wallet)
3. Poll status          →  pending → processing → completed | failed | cancelled
4. (Optional) Cancel    →  before settlement window closes

ℹ️

Payments are idempotent per external_id: send a unique external_id on each payment request and safely retry with the same value without duplicating charges.

Step 1: Decode a Barcode

Before authorizing, decode the boleto barcode to confirm amount, due date, and beneficiary:

curl -X POST https://api.brzip.com.br/api/v1/payments/boleto/decode \
  -H "Authorization: Bearer <your-jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "barcode": "34191.09008 61234.678901 23456.789012 1 100000000025000"
  }'

Response (200 OK):

The response wraps the provider's raw decode payload under data.data, plus a settlement_mode marker:

{
  "success": true,
  "data": {
    "data": {
      "...": "raw provider (Celcoin) boleto data — amount, due date, beneficiary, fine, interest, discount, etc."
    },
    "settlement_mode": "prefunded"
  }
}

ℹ️

data.data is the underlying provider's boleto payload passed through as-is (currently Celcoin). Field names inside it follow the provider's contract and are not remapped by the BRZ API. settlement_mode is always "prefunded".

Step 2: Authorize Payment

Submit the payment. The wallet is debited immediately:

curl -X POST https://api.brzip.com.br/api/v1/payments/boleto \
  -H "Authorization: Bearer <your-jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "7e0a1b2c-3d4e-5f6a-7b8c-9d0e1f2a3b4c",
    "barcode": "34191090086123467890123456789012110000000002500",
    "amount": 250.00,
    "cpf_cnpj": "12345678901",
    "description": "Invoice #1234"
  }'

Request fields:

Field Type Required Description
external_id string Yes Your unique payment ID — used for idempotency
barcode string Yes Boleto barcode / digitable line
amount number Yes Amount to pay (must be > 0)
cpf_cnpj string Yes CPF/CNPJ of the payer
scheduled_for string No Schedule date (YYYY-MM-DD)
description string No Free-text description

Response (201 Created):

{
  "transaction_id": "9f3d2a1b-4c5e-6f7a-8b9c-0d1e2f3a4b5c",
  "external_id": "7e0a1b2c-3d4e-5f6a-7b8c-9d0e1f2a3b4c",
  "status": "pending",
  "amount": "250.00",
  "currency": "BRL",
  "created_at": "2026-07-22T14:30:00Z"
}

⚠️

A 201 Created response means the payment was accepted for processing — not that it has settled. The initial status is pending. Poll the status endpoint to confirm settlement.

Errors:

HTTP Code Meaning
400 INVALID_BARCODE Barcode failed checksum validation
400 AMOUNT_MISMATCH Submitted amount differs from decoded amount
400 BOLETO_EXPIRED Boleto past its expires_at date
402 INSUFFICIENT_FUNDS Wallet balance too low
409 DUPLICATE_PAYMENT Same barcode already paid by this account
409 IDEMPOTENCY_CONFLICT external_id reused with different parameters

Step 3: Check Payment Status

curl -X GET https://api.brzip.com.br/api/v1/payments/boleto/{paymentId} \
  -H "Authorization: Bearer <your-jwt>"

Response:

{
  "transaction_id": "9f3d2a1b-4c5e-6f7a-8b9c-0d1e2f3a4b5c",
  "external_id": "7e0a1b2c-3d4e-5f6a-7b8c-9d0e1f2a3b4c",
  "status": "completed",
  "amount": "250.00",
  "currency": "BRL",
  "created_at": "2026-07-22T14:30:00Z",
  "updated_at": "2026-07-22T14:31:45Z"
}

Payment statuses:

Status Description
pending Accepted, not yet submitted to the provider
processing Submitted to the provider, awaiting confirmation
completed Settlement confirmed
failed Provider rejected — funds returned to wallet
cancelled Cancelled before settlement
blocked Held for manual review
refunded Payment reversed
pending_manual_review Awaiting manual review
expired Payment window elapsed

Typical settlement time: 30 seconds to 2 minutes for processing → completed.

Recommended polling strategy:

async function waitForPayment(paymentId, token) {
  const POLLS = 10;
  const DELAY = 5000; // 5s

  for (let i = 0; i < POLLS; i++) {
    const resp = await fetch(
      `https://api.brzip.com.br/api/v1/payments/boleto/${paymentId}`,
      { headers: { Authorization: `Bearer ${token}` } }
    );
    const data = await resp.json();

    if (data.status !== "pending" && data.status !== "processing") return data;
    await new Promise(r => setTimeout(r, DELAY));
  }
  throw new Error("Payment still processing after 50s — use webhooks");
}

ℹ️

For production, subscribe to the boleto.payment.completed webhook event instead of polling. See the Webhooks guide.

Step 4: Cancel a Payment (Optional)

Cancellation is only possible while the payment is still in processing:

curl -X DELETE https://api.brzip.com.br/api/v1/payments/boleto/{paymentId} \
  -H "Authorization: Bearer <your-jwt>"

Response (200 OK):

Like decode, the response wraps the provider's raw cancellation payload under data.data:

{
  "success": true,
  "data": {
    "data": {
      "...": "raw provider (Celcoin) cancellation payload"
    },
    "settlement_mode": "prefunded"
  }
}
HTTP Code Meaning
409 PAYMENT_NOT_CANCELLABLE Payment already settled or failed

Webhook Events

Subscribe to these events in your webhook configuration:

Event When
boleto.payment.created Payment accepted and created
boleto.payment.completed Provider confirmed settlement
boleto.payment.failed Provider rejection — funds returned
